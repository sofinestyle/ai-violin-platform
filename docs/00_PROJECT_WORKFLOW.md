## 1. 文档目的

本文档用于规定 AI Violin Platform 的长期项目工作方式，解决 ChatGPT 对话压缩、跨会话记忆丢失、需求漂移和文档不同步问题。

---

## 2. 唯一事实来源

GitHub 仓库中的 Markdown 文档是项目唯一事实来源。

聊天内容、临时讨论和未提交草稿不能替代 GitHub 文档。

---

## 3. 固定角色分工

### 3.1 项目经理

项目经理由用户本人担任。

### 3.2 ChatGPT 负责

- 产品经理
- 系统架构师
- AI 架构设计师
- 数据库设计师
- UI/UX 设计师
- 技术路线规划
- 生成 Codex 任务
- 检查文档同步状态
- 重新读取 GitHub 后进入下一阶段

### 3.3 Codex 负责

- 更新 Markdown 文档
- 前端开发
- 后端开发
- 数据库开发
- API 开发
- Bug 修复
- 重构
- 测试
- Git Commit
- Git Push
- 中文反馈执行结果

---

## 4. 标准项目流程

项目采用以下固定流程：

```text
需求讨论
↓
方案设计
↓
项目经理确认（Freeze）
↓
ChatGPT 自动生成中文 Codex 指令
↓
Codex 更新 GitHub 文档
↓
Codex Commit
↓
Codex Push
↓
Codex 中文反馈完成情况
↓
ChatGPT 重新读取 GitHub 最新文档
↓
确认同步无误
↓
进入下一阶段
```

---

## 5. Freeze 规则

- 只要项目经理确认，即视为 Freeze。
- Freeze 后不能直接进入下一阶段。
- 必须先同步 GitHub。
- 未完成文档同步、Commit 和 Push 前，不得开始下一阶段。
- 已 Freeze 的内容原则上不得随意修改。
- 如确需修改，必须说明原因、影响范围，并重新确认。

---

## 6. ChatGPT 自动行为

项目经理确认后，ChatGPT 不需要等待再次提醒，应自动：

1. 判断需要新增或修改哪些文档。
2. 生成完整的中文 Codex 指令。
3. 要求 Codex Commit 和 Push。
4. 要求 Codex 用中文反馈。
5. 收到完成反馈后重新读取 GitHub。
6. 确认文档一致后再继续下一阶段。

---

## 7. Codex 完成反馈规范

Codex 完成任务后必须用中文报告：

```text
本次任务状态：
已新增文件：
- ...
已修改文件：
- ...
未修改文件：
- ...
Commit SHA：
...
Push 状态：
成功 / 失败
冲突或警告：
无 / 具体说明
```

## 8. 新会话启动规则

任何新的 ChatGPT 会话在继续项目之前，应优先读取：

- README.md
- docs/00_PROJECT_GOVERNANCE.md
- docs/00_PROJECT_WORKFLOW.md
- docs/05_CURRENT_HANDOFF.md
- 当前阶段相关文档

读取完成后，应自动遵守工作流，不再要求项目经理重复说明。

---

## 9. 文档语言规范

- Markdown 正文统一使用中文。
- ChatGPT 与项目经理沟通使用中文。
- Codex Task 使用中文。
- Codex 完成反馈使用中文。
- 代码、变量、函数、类名、API、数据库字段、枚举值、技术框架名称使用英文。

---

## 10. 架构稳定原则

对于已经 Freeze 的目录结构、文档结构、系统架构、数据库结构和模块划分，非必要情况下不得新增、删除或大幅调整。

只有以下情况允许提出调整：

1. 存在明显设计缺陷，继续使用会导致大量返工。
2. 新需求无法在现有架构内合理扩展。
3. 出现明确的技术限制。
4. 项目经理明确要求调整。

调整优先级：

```text
遵循已确认架构
↓
在现有架构内扩展
↓
必要时优化
↓
确有必要才调整架构
```

---

## 11. 文档新增控制规则

- 新内容优先写入已有文档。
- 新增文档前必须判断现有文档是否可以承载。
- 非必要不新增目录和文件。
- 新增文档必须有明确、长期、不可替代的职责。
- 未经项目经理确认，不得因为“更完整”或“更专业”自行新增文档。

---

## 12. 每次进入下一阶段前的检查

ChatGPT 应检查：

- 上一阶段是否 Freeze。
- GitHub 是否已同步。
- docs/05_CURRENT_HANDOFF.md 是否已更新。
- CHANGELOG.md 是否已记录。
- Codex 是否已反馈 Commit SHA 和 Push 状态。
- 是否存在未完成的 Codex 任务。
