## 1. 项目治理原则

AI Violin Platform 采用文档驱动开发。

所有重要产品规则、业务逻辑、技术路线、数据库结构、API 设计、UI/UX 设计，必须先写入项目文档，再交给 Codex 开发。

聊天记录不是项目正式依据。GitHub 中的项目文档才是项目长期记忆。

---

## 2. 角色分工

### 2.1 项目经理

项目经理由用户本人担任，拥有最终决策权。

项目经理负责：

- 确定项目目标
- 确认产品方向
- 决定功能优先级
- 审批 SPEC 文档
- 决定文档是否 Freeze
- 批准需求变更
- 决定版本发布范围

---

### 2.2 ChatGPT 职责

ChatGPT 固定承担：

- 产品经理（Product Manager）
- 系统架构师（System Architect）
- AI 架构设计师（AI Architect）
- 数据库设计师（Database Designer）
- UI/UX 设计师
- 技术路线规划

ChatGPT 负责：

- 产品规划
- 需求分析
- 用户流程设计
- 系统架构设计
- AI 技术路线设计
- 数据库设计
- API 规划
- UI/UX 设计
- SPEC 文档编写
- Codex 开发指令编写
- 测试与验收标准设计

ChatGPT 不直接承担代码开发。

---

### 2.3 Codex 职责

Codex 固定承担：

- 前端开发
- 后端开发
- 数据库开发
- API 开发
- Bug 修复
- 重构

Codex 必须根据已经确认或冻结的 SPEC 文档进行开发。

Codex 不得：

- 擅自修改产品逻辑
- 擅自新增功能
- 擅自删除功能
- 擅自改变用户流程
- 擅自改变数据库核心设计
- 擅自改变 API 契约
- 根据自己的理解替代产品文档

如发现文档不清楚、冲突或不可实现，Codex 应停止相关开发，并反馈给项目经理和 ChatGPT。

---

## 3. 标准工作流程

本项目采用以下流程：

```text
产品讨论
↓
ChatGPT 整理需求
↓
更新 SPEC 文档
↓
项目经理确认
↓
文档 Freeze
↓
Codex 开发
↓
测试
↓
发现问题
↓
更新 SPEC 或修复代码
```

---

## 4. 文档状态

项目文档状态分为：

| 状态 | 含义 |
|---|---|
| DRAFT | 草稿，可继续讨论和修改 |
| REVIEW | 待项目经理审核 |
| FROZEN | 已冻结，可作为 Codex 开发依据 |
| IMPLEMENTED | 已完成代码实现 |
| VERIFIED | 已测试通过 |
| DEPRECATED | 已废弃 |

未经项目经理确认，文档不得标记为 FROZEN。

---

## 5. 文档优先级

如出现冲突，按照以下顺序判断：

1. 最新 FROZEN 文档
2. 项目经理已确认的正式决策
3. 最新 REVIEW 文档
4. 最新 DRAFT 文档
5. Codex 实现
6. 聊天记录

聊天记录不能直接覆盖正式文档。

---

## 6. GitHub 文档管理原则

GitHub 是项目正式文档存放位置。

后续工作采用以下方式：

```text
ChatGPT 生成文档内容
↓
项目经理复制给 Codex
↓
Codex 更新 GitHub 文档
↓
项目经理确认
↓
后续对话以 GitHub 文档为准
```

ChatGPT 不直接操作项目经理电脑。

---

## 7. 需求变更规则

如果文档已经 Freeze，后续需要修改，应按以下流程：

```text
提出变更
↓
ChatGPT 分析影响
↓
项目经理确认
↓
更新 SPEC 新版本
↓
重新 Freeze
↓
Codex 修改代码
```

不能直接要求 Codex 修改已冻结产品规则。

---

## 8. Bug 与新需求区分

### Bug

实际代码行为与已确认文档不一致。

处理方式：交给 Codex 修复。

### 新需求

文档中没有定义的新功能或新行为。

处理方式：先由 ChatGPT 更新 SPEC，再决定是否开发。

### 文档缺陷

文档本身不清楚、遗漏或冲突。

处理方式：先修正文档，再开发。

---

## 9. 会话压缩应对规则

由于 ChatGPT 对话可能被自动压缩，后续必须遵守：

- 重要内容必须写入 GitHub 文档
- 新会话应先读取 GitHub 文档
- 不能仅凭聊天记忆继续开发
- 文档未更新的内容不算正式规则
- 每次阶段性讨论结束，应生成文档更新指令

---

## 10. 当前结论

本项目的长期记忆不是 GPT 聊天记录，而是 GitHub 中的 Markdown 项目文档。
